# 2026新潟記念 Stage A内部分解研究（Stage A Internal Decomposition Research）

**作成日**: 2026-09-02
**目的**: `docs/2026-niigata-kinen-prediction-error-analysis.md`で判明した主要事実
（Base Abilityが実際の上位3頭を正しく抽出していた／稍重の反事実分析では順位が変わらなかった／
ゾロアストロのcourse補正誤記は実際にはネットマイナスだった／斤量は現状一切モデル化されていない／
3歳馬成長だけではゾロアストロ優勝を説明できない／Stage Bは全馬中立だったため実質的に
Stage Aのみで最終順位が決まっていた）を踏まえ、「Stage A内部で、なぜ各馬にその
順位・点差がついたのか」を完全に分解する。

**スコープ制約（本ラウンドも厳守）**:
- コード・productionデータ・パラメータは一切変更しない（読み取り専用のスクラッチスクリプトで
  既存の凍結済み関数`calculateBaseAbility()`・`computeSuitabilityV1()`を実行しただけ。
  スクリプトは分析後に削除済み）。
- Base Ability V1／Suitability V1／`PLACKETT_LUCE_TEMPERATURE`は一切変更しない。
- 実データのみを使用。推測・捏造値は一切使用しない。データが無い箇所は
  「NOT_EVALUATED」「不明」と明記する。
- 本ラウンドの結論から新しい係数・component・補正を勝手に実装しない。

**対象馬**: ダノンシーマ（3着）・ロデオドライブ（2着）・ゾロアストロ（1着）・
バレエマスター（10着）・ジュンブロッサム（9着）・サヴォーナ（4着）・
アーバンシック（5着、参考）

**手法**: `getHorseRecentRaces()` → `predictionCutoffAt`（2026-08-28T03:03:03.357Z）以前の
`dataKind=real`の実績のみを抽出 → `calculateBaseAbility()`（直近5走の単純平均）と
`computeSuitabilityV1()`（新潟・芝・2000m・going=UNKNOWN sentinel）を実際に実行し、
Stage Aの`effectiveAbility = baseAbility × overallSuitabilityPercent / 100`を
馬ごとに手計算で再現・検証した。

`calculateBaseAbility`は直近`RECENT_RACE_COUNT=5`走（不足時はそれ未満）の`raceScore`の

### 1-2. 上位3頭（ダノンシーマ／ロデオドライブ／ゾロアストロ）の点差の内訳

`raceScore = memberLevelScoreAtRace×0.30 + timeGapScore×0.25 + raceTimeScore×0.25 + final3FScore×0.15 + weightScore×0.05`
の5項目のうち、使用5走（ロデオドライブは4走）平均で比較する。

| 項目（平均） | ダノンシーマ | ロデオドライブ | ゾロアストロ |
|---|---|---|---|
| memberLevelScoreAtRace | **72.78** | 66.50 | 70.10 |
| timeGapScore | 90.00 | 90.00 | 82.30 |
| raceTimeScore | 72.00 | 70.00 | 70.00 |
| final3FScore | 83.16 | **87.83** | 81.36 |
| weightScore | 66.32 | 70.28 | 70.00 |
| **raceScore平均（=baseAbility）** | **78.3** | **76.7** | **74.8** |

**数値的に読み取れること**:

1. **ダノンシーマの首位は主にmemberLevelScoreAtRace（対戦相手の質）に由来する。**
   彼女の5走（目黒記念・阪神大賞典・白富士S・比叡S・兵庫特別）はいずれも重賞または
   相応のレベルのオープン特別で、平均72.78は3頭中最高。これはweight30%と最も重いため、
   raceScore全体への寄与も最大。ロデオドライブの66.50（3歳限定戦中心）・ゾロアストロの
   70.10（皐月賞は高いが2歳戦・きさらぎ賞は相対的に低い）を明確に上回っている。
   **これは「格上と戦って崩れなかった」という実績が正しくraceScoreへ反映された、
   モデルとして妥当な差である。**

2. **timeGapScoreもダノンシーマ・ロデオドライブが90.0（ほぼ満点）で並び、
   ゾロアストロは82.30とやや低い。** これは皐月賞（12着、timeGap=1秒差相当でtimeGapScore=62）
   が平均を押し下げているため。皐月賞1走の影響が大きい。

3. **final3FScoreはロデオドライブが3頭中最高（87.83）。** 上がり3F重視の項目で、
   彼女の4走はいずれも上がりの速い決着だった若駒レースが中心（88.6/81.6/89.9/91.2）。
   ダノンシーマは83.16、ゾロアストロは81.36とやや劣る。

4. **weightScoreはダノンシーマが66.32と3頭中最低。** これは彼女が古馬牝馬として
   58kg前後を背負ったレースが多く、`weightScore.ts`が「フィールド中央値に対して重い」と
   評価した結果。ただしweightScoreの`RACE_SCORE_WEIGHTS`内シェアは5%のみであり、
   raceScore全体への影響は限定的（0.30の差×0.05=0.015点程度）。

**結論（Base Ability上位3頭の順位について）**: ダノンシーマの首位は
「相手の質（memberLevelScoreAtRace, 30%ウェイト）」という最も重いraceScore構成要素で
最も優れていたことに起因する、モデル上一貫性のある結果である。ロデオドライブは
「上がり3F（final3FScore, 15%ウェイト）」で3頭中最高だが、ウェイトが軽いため
raceScore総合では2位にとどまった。この「上がり3Fの強さ」は、実際のレースが
稍重の上がり勝負（勝ち時計1:59.6、上がり最速級の決着）だったことと関連する可能性が
あるが、**これは1レースの観察に基づく仮説であり、final3Fのウェイトを引き上げる
根拠にはならない**（後述12-2「絶対にやらないこと」参照）。

## 3. ゾロアストロ重点検証

### 3-1. Base Ability過小評価の可能性

74.8は7頭中3位で、5走の平均も皐月賞（12着、raceScore=70.2）という明確な凡走を含んでいる。
皐月賞1走を除いた残り4走の平均は`(76.5+78.5+74.9+73.9)/4=75.95`となり、
含めた場合の74.8よりわずかに高い。**しかしこれは「除外すべき」という意味ではない**——
`calculateBaseAbility`は直近5走を機械的に使用する仕様であり、皐月賞を恣意的に
除外することはV1凍結ルールに反する。凡走1走を含めてもなお74.8は7頭中3位であり、
「過小評価されて実際より低く出た」と断定できる根拠はない。**むしろBase Abilityは
彼女を実際の優勝馬として3位に正しく位置づけていた。**

### 3-2. Suitability過小評価の可能性

上記2-2の通り、course componentは実際には**ネットマイナス**（99.6%）であり、
過小評価どころか「実際にはやや割り引かれていた」。distanceも99.2%とマイナス方向。
**Suitability全体が彼女の最終スコアを押し下げる方向に働いていた**という事実は、
彼女が優勝したという結果と整合しない——つまりSuitabilityが「彼女の勝利を
正しく予見していた」わけではなく、むしろ逆方向だった。

### 3-3. その他の未実装要因の可能性

- **斤量**: 優勝したゾロアストロの今回の斤量データは本レポートのスコープ外
  （出馬表の確定重量データを別途参照する必要がある）が、7節で述べる通り
  現状weightは「今回の斤量」を一切評価に使っていない。既知の未実装要因として
  記録する。
- **3歳馬（世代）としての成長曲線**: `docs/2026-niigata-kinen-prediction-error-analysis.md`
  で既に検証済み（3歳馬成長だけでは優勝を説明できないと結論済み）。本レポートで
  再検証はしない。
- **展開・位置取り**: `runningStyleLeanScore`ではゾロアストロは+0.333（追込寄り）。
  実際のペースはS（スロー）で、道中の位置取りがどう功を奏したかはStage Bの
  `racePacePrediction.ts`（診断専用、Stage Aには非接続）を参照すれば診断的な
  示唆はあるが、これはStage Aの範囲外である。

### 3-4. 純粋な競馬的偶然性（フォトフィニッシュ）の可能性

`finalRaceAbility`は3頭とも同一（Stage Bが全馬中立のため）で、
ダノンシーマ80台・ロデオドライブ77台・ゾロアストロ74台という前提で
（※実際の数値はeffectiveAbilityそのものであり、
ダノンシーマ79.79／ロデオドライブ76.7／ゾロアストロ74.35）、
実際の着差はアタマ・アタマ（1〜3着）という極めて僅差だった。

**点差とタイム差の整合性の検証（6節「点差検証」参照）**: モデル上の点差
（79.79 vs 76.7 vs 74.35、約3.1pt・2.35pt差）を「タイム差に換算した場合、
アタマ差×2＝ごく僅かな時間差」と直接比較する換算式は本モデルには存在しない
（`raceScore`のtimeGapScoreは過去走のタイム差を評価する項目であり、
点差そのものを着差秒数に逆変換する機能はない）。よって「79.79 vs 74.35の
約5.4ptの差がアタマ・アタマの僅差と数学的に矛盾するか」を厳密に検証することは
**現状のモデルの機能範囲では不可能**であり、これ以上の定量的な結論は出せない。
6節で述べる「馬ごとの過去走内変動幅」との比較が、現状唯一可能な間接的な
妥当性検証である。

**結論**: ゾロアストロの優勝は、Base Ability・Suitabilityのいずれによっても
「事前に強く予見されていた」わけではない（Suitabilityはむしろマイナス方向）。
Stage Aの3位という評価自体は妥当な範囲内だが、実際の1着という結果とStage Aの
序列との差は、現行モデルが説明できる要因（相手関係・上がり3F等）だけでは
埋まらず、**斤量・展開・純粋な競馬的偶然性など、未実装または定量化不能な
要因の複合である可能性が高い**という以上の断定はできない。

## 4. バレエマスター／ジュンブロッサム 完全分解

### 4-1. バレエマスターの二重カウント構造

- Base Ability: 72.4（7頭中4位相当、中位）
- Suitability: distance +1.8pt（n=5・high、信頼できる根拠）＋
  **course +2.0ptとgate +1.4ptが、いずれも同一の1走（2026-05-16新潟大賞典）から算出**
- overallSuitabilityPercent = 101.7%
- effectiveAbility = 72.4 × 101.7% = 73.63（Stage Aで4位相当まで押し上げ）

**なぜ同一レースが2つのcomponentに二重寄与するのか（コード上の理由）**:
`computeGateSuitabilityV1`（gate component）はHorseEvidence優先で、
「対象レースと**競馬場×馬場×距離が完全一致**する馬自身の過去走」を要求する。
course componentは「競馬場が一致する馬自身の過去走」のみを要求する（距離条件は
courseより緩い）。バレエマスターの場合、**その唯一の該当走（新潟大賞典）が
たまたま新潟×芝×2000mという対象レースとの完全一致条件も満たしてしまった**ため、
courseとgateの両方の判定条件を同時に満たし、同じ1つの実績（着2、raceScore=77.3、
彼女の平均72.4を上回る好走）が2つの独立したcomponentとして加算される結果となった。

**分類**: これはバグではない——course・gateはそれぞれ独立した目的
（「競馬場適性」「枠・コース形態適性」）を持つcomponentとして設計されており、
たまたま根拠データが1件しかなく、かつその1件が両方の条件を満たしただけである。
しかし、**根拠データが実質1件（n=1・conf=low）しかないにもかかわらず、
2つのcomponentから加算されることで見かけ上の補正効果が実際より大きく見える**
という構造的な性質がある。今回のケースでたまたま起きただけなのか、それとも
「新潟のようにcourse一致条件とgate完全一致条件が同一走で重なりやすいコース」
で構造的に起きやすい現象なのかは、**今回の1レースだけでは判別できない。**
30レース規模の検証が必要（B分類）。

### 4-2. ジュンブロッサムとの対比（二重カウントなし）

- Base Ability: 72.7（7頭中5位）
- Suitability: distance +0.4pt（n=5・high）＋course +0.7pt
  （2026-08-08関越S、新潟×芝×1800m、n=1・low）
- 関越Sは**距離が1800mで対象の2000mと一致しないため、gateはNOT_EVALUATEDのまま
  ——二重カウントは発生していない。**
- overallSuitabilityPercent = 100.6%
- effectiveAbility = 72.7 × 100.6% = 73.14

さらに注目すべき点として、**この関越Sでジュンブロッサムは実際には9着だった**。
それでもraceScore=74.3（彼女自身の5走平均72.7を上回る）となり、courseに
軽微プラスとして寄与している。これはraceScoreが着順そのものではなく
「timeGap・raceTime・memberLevel・final3F等の複合指標」であるため、
**「9着でも相手が強く僅差だった」ような内容であればraceScoreが着順以上に
評価されうる**、というモデルの仕様通りの挙動である。バグではないが、
「course適性の根拠が、実際には掲示板外の着順だった」という事実は、
Stage Aの人間向け説明で誤解を招きやすい点として記録する。

### 4-3. 両馬の分類

- バレエマスターの二重カウント構造: **B（30レース等で検証すべき）**。
  新潟大賞典のような「course一致とgate完全一致が同一走で重なるケース」が
  他の馬・他のコースでどの程度発生するかを確認しないと、構造的な問題か
  偶然かを判断できない。

  raceScoreの設計思想（着順だけでなく相手関係・タイム差を含めて評価する）
  通りの正常な挙動であり、修正の必要はない。ただし人間向け説明表示では

## 5. サヴォーナ過小評価分析

Stage Aで8位（実際は4着）だった主因を、Base Ability／Suitability／Stage Bの
3経路で切り分ける。

| 経路 | 数値 | 順位への影響 |
|---|---|---|
| Base Ability | 70.2（7頭中最下位） | **主因** |
| Suitability | 99.6%（ほぼ中立、n=5・high） | ごく軽微（-0.6%程度） |
| Stage B | 全馬中立（100%） | 影響なし |

**Base Abilityが最下位である直接の理由**: 直近5走に七夕賞（2026-07-12、着10、
raceScore=62.0）という明確な凡走が含まれており、これが単純平均を大きく
押し下げている。他の4走（76.0/70.7/72.2/70.2）はいずれも70前後で安定しているが、
`calculateBaseAbility`は**直近走ほど重視する仕組みがない単純平均**のため、
七夕賞1走の影響が他の4走と同じ重みで反映される。仮に七夕賞を除いた4走平均を
参考計算すると`(76.0+70.7+72.2+70.2)/4=72.28`となり、対象7頭の中で
ジュンブロッサム（72.7）・バレエマスター（72.4）と同水準まで上がる。

**ただし、この「七夕賞を除く」という操作はV1ルール上許可されない**
（直近5走を機械的に使う仕様が凍結済み）。ここで示しているのは
「なぜ過小評価に見えるのか」の内訳説明であり、除外を提案するものではない。

**分類**: **F（競馬の偶然性として許容すべき）に近いが、構造的な論点として
B（30レース等で検証すべき）も該当する。** 単純平均という設計自体が
「直近1走の凡走が5走平均へ均等に影響する」という性質を持つことは
V1で意図された仕様であり、今回のケース単独では変更の根拠にならない。
しかし「直近走に極端な凡走（フォトフィニッシュや大敗ではなく、通常の
着順不振）が1つ混じった場合にBase Abilityがどの程度過小に振れるか」は、
複数レースでの検証に値するテーマである。

## 6. finalRaceAbilityの点差（score spacing）検証

**重要な注意**: 本節は勝率変換（Plackett-Luce・Temperature）の校正問題とは
明確に切り離す。`docs/win-probability-calibration-v1-research.md`で既に
勝率変換側の論点は整理済みであり、本節はそれとは独立に
「finalRaceAbilityという点数自体の間隔（スケール）が実力差を適切に
表現できているか」だけを検証する。

### 6-1. 馬間の点差（between-horse spacing）

対象7頭のeffectiveAbility: ダノンシーマ79.79／ロデオドライブ76.70／
ゾロアストロ74.35／ジュンブロッサム73.14／バレエマスター73.63／
アーバンシック72.17／サヴォーナ69.92。

- 上位3頭間の差: ダノンシーマ-ロデオドライブ=3.09pt、ロデオドライブ-ゾロアストロ=2.35pt
- 7頭全体のレンジ: 79.79 - 69.92 = 9.87pt

### 6-2. 馬自身の過去走内変動幅（within-horse volatility）

各馬の直近5走のraceScore自体が、レースごとにどの程度ばらついているかを見る。

| 馬名 | raceScore範囲 | 変動幅 |
|---|---|---|
| ダノンシーマ | 75.1〜83.9 | **8.8pt** |
| ロデオドライブ | 72.4〜79.0 | 6.6pt |
| ゾロアストロ | 70.2〜78.5 | 8.3pt |
| バレエマスター | 67.0〜77.3 | 10.3pt |
| ジュンブロッサム | 67.3〜74.5 | 7.2pt |
| サヴォーナ | 62.0〜76.0 | 14.0pt |
| アーバンシック | 64.5〜81.6 | 17.1pt |

**観察**: ダノンシーマとゾロアストロの馬間の差（3.09pt＋2.35pt=5.44pt）は、
**両馬自身の1走ごとのraceScore変動幅（8.8pt、8.3pt）よりも小さい。**
つまり「今日たまたまダノンシーマが少し悪い日で、ゾロアストロが少し良い日だった」
という程度の変動で、モデル上の点差は十分に覆りうる範囲にある。この観点からは、
**finalRaceAbilityの馬間点差が「不自然に大きすぎる」とは言えず、
むしろ通常の単一レースのノイズと同程度かそれ以下**という評価になる。

**ただし、これは「点差が正しい」ことの証明ではない。** 「馬自身の変動幅と
同程度の馬間点差である」という事実は、(a) 点差が実力差を適切なスケールで
表現できている可能性、と (b) 点差のスケール自体が実力差にほとんど
意味を持たず、単なるノイズと不可分になっている可能性、の**両方と整合する**。
現行モデルにはこの2つを判別する手段がない。

**分類**: **C（追加データが必要）**。複数レースでfinalRaceAbilityの点差と
実際の着差・タイム差の相関を検証しない限り、スケールの妥当性は判断できない。
今回の1レースの結果だけでは「点差が広すぎる」とも「適切」とも断定できない。

## 7. 斤量（研究のみ・実装なし）

### 7-1. 現状の確認（再確認）

`grep`により、`RaceEntryInput.carriedWeight`（今回のレースで割り当てられる斤量）は
`predictionSnapshot.ts`・`finalRaceAbility.ts`・`suitabilityV1.ts`のいずれの
計算ロジックからも参照されていないことを再確認した。`weightScore.ts`が評価するのは
**過去の各レースにおける、その馬自身が背負った斤量とそのレースのフィールド中央値との
relative差**であり、raceScoreの構成要素として5%のウェイトで寄与するのみ。
**「今回のレースで何kg背負うか」を評価する経路はコード上どこにも存在しない。**

### 7-2. どの層に実装すべきかの検討（提案のみ、実装しない）

| 候補レイヤー | 根拠 | 懸念 |
|---|---|---|
| Base Ability層に追加 | 過去の斤量経験を蓄積して評価するweightScoreの発想と一貫性がある | Base Abilityは「馬自身の絶対能力」を測る設計思想であり、今回の斤量という「レース条件」を混ぜると設計思想（凍結ルール5「baseAbility=0はデータ不足」等）と衝突するおそれ |
| Suitability層に追加 | 「今回の条件への適合度」という設計思想（distance/course/going/gateと同列）に自然に収まる | 新規componentの追加はV1凍結ルールに反するため、V2として明示的に切り出す必要がある |
| 新設「Race Condition」層 | 斤量・枠順・馬体重増減など「当日条件」をまとめて扱う新層として独立させる | 設計コストが大きい。Stage BのInput Contract（CHECKPOINT14D.3で設計済み）との重複整理が必要 |

**現時点での所見（結論ではなく提案）**: 斤量はSuitability（「今回の条件への
適合度」という既存の設計思想）に最も自然に収まるように見えるが、
「新設のRace Condition層」の方が将来的に枠順・馬体重増減等も含めて拡張しやすい
という考え方もあり得る。**どちらが適切かは、本レポート単独では決定できない。**

### 7-3. 複数レースで検証すべき項目（提案）

1. 過去の斤量差（例: ハンデ戦・古馬牝馬混合戦）が実際の着順・raceScoreと

2. 斤量差が「大きい」場合（4kg以上等）に限定して影響が出るのか、

3. 距離別（短距離ほど斤量の影響が大きいという一般論があるか）に
   影響度が異なるかを検証する。

**分類**: **B（30レース等で検証すべき）**。今回1レースの結果

斤量補正を実装することは明確に禁止事項に該当する。

## 8. Stage Bについて（非常に重要）

ユーザーの三択（(a)たまたま中立判定になった／(b)必要な入力データが無いため
常に中立に近い状態だった／(c)Stage Bがまだ実質未完成なのか）について、
`paceScenarioFactor`と`trackBiasFactor`はそれぞれ**異なる答え**になることを、
コードを根拠に明確に区別する。

### 8-1. paceScenarioFactor（ペース）の中立性 = 「(a) たまたま中立」に該当

`paceScenarioFactor.ts`の計算式:
```
raw = 100 + PACE_SCENARIO_AMPLITUDE(5) × PACE_LEVEL_SCORE × leanScore
PACE_LEVEL_SCORE: slow=-1, average=0, high=+1
```

今回のレースは`predictedPace.ts`の`classifyPredictedPace()`が
`nigeCandidateCount=0, senkoCandidateCount=2`という実際のフィールド構成から
**「average」と判定した**（実際の公式ペースは「S」だったが、この関数は
"slow"の条件を`nigeCandidateCount===0 && senkoCandidateCount===0`という
厳格な条件で定義しており、今回はsenkoCandidateCountが2いたため条件を
満たさなかった）。「average」の場合、`PACE_LEVEL_SCORE=0`となり、
**どの馬の`leanScore`が何であってもraw=100（完全中立）に数学的に固定される。**

これは**今回のフィールド構成（senko候補が2頭いたこと）に起因する
データ依存の結果**であり、逃げ候補が2頭以上いる別のフィールドであれば
"high"に、両方0頭であれば"slow"に分類され、その場合は中立にならない。
**→ (a)「たまたま」に該当。ただし「たまたま」という言葉が示唆するような
完全な偶然ではなく、「今回のフィールドの脚質構成と、離散的な3分類ルールの
組み合わせの結果」という意味でのdata-dependentな中立化である。**

### 8-2. trackBiasFactor（トラックバイアス）の中立性 = 「(b)常に中立」に該当

`trackBias.ts`の`resolveTrackBias(manualTrackBias, autoTrackBias, target)`は、
`manualTrackBias`と`autoTrackBias`の両方が`null`の場合、中立（100%、
confidence="low"、usedSource="neutral"）を返す設計。CHECKPOINT14D.3の監査で
確認済みの通り、**`autoTrackBias`（トラックバイアスの自動検出）はV1では
実装されていない**（`finalRaceAbility.ts`のコード・コメント双方で確認済み）。
今回`manualTrackBias`も人間から供給されなかった（赤倉特別の診断結果を
「MIXED/INCONCLUSIVE」として扱い、これを`manualTrackBias`として
無理にコード入力しないという判断をCHECKPOINT14D.4で下した）。

**→ (b)「必要な入力データが無いため常に中立に近い状態だった」に該当。
これは今回のレース固有の現象ではなく、`autoTrackBias`の自動検出パイプラインが
実装されるか、毎回人間が手動で観測値を入力しない限り、
今後のどのレースでも同じく中立になり続ける、構造的に恒常的な状態である。**

### 8-3. (c)「Stage Bがまだ実質未完成なのか」について

`computeRaceContextFactor()`自体のロジック（paceScenarioFactorとtrackBiasFactorの
掛け算、evaluatedフラグの管理等）は正しく動作しており、「壊れている」わけではない。
しかし、**2つの入力のうち1つ（トラックバイアス自動検出）が構造的に未実装であり、
もう1つ（ペース分類）も"average"/"slow"/"high"という3値の粗い離散分類のため
中立になりやすい**、という意味では、**Stage Bは「エンジンとしては動くが、
実質的に有効な補正を生成できる条件が限定的」という状態にある。**
これは(c)を部分的に支持する見方だが、「未完成で壊れている」というより
「設計上の入力データ源がまだ揃っていない」という表現がより正確である。

**分類**:
- paceScenarioFactorの中立性: **A（現状維持すべき、ただし将来の連続値ベース分類は
  Gate 30レース研究等で別途検討の価値あり＝B寄り）**
- trackBiasFactorの構造的中立性: **C（追加データが必要）**。自動検出パイプラインの
  実装、または人間観測値の系統的な収集フローが無ければ解消しない。
