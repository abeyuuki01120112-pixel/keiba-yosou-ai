# 2026新潟記念 Prediction Error Analysis / Improvement Research

事前予想と実結果を、実コード・実データを使ってAI内部の各計算段階まで遡って比較した
研究レポート。**今回はコード変更・パラメータ変更を一切行っていない。** 反実仮想
シミュレーション（後述）も、既存の凍結関数を異なる引数で呼び出しただけであり、
production data・persisted snapshotへの書き込みは一切発生していない。

---

## 0. 分析手法の前提

- Base Ability・Suitability V1・finalRaceAbilityの各値は、CHECKPOINT14D.2/14D.4で
  実コード実行により確定済みの内部精度値をそのまま使用した（再計算による差異なし）。
  実際のレースの通過順位（コーナー通過順）そのものはユーザーから提供されておらず、
  本レポートでは取得していない。**item5（展開・位置取り）は、各馬の過去の脚質分布
  （既存Historical Position Profileの実データ）と公式ラップ・ペース判定から推論した
  ものであり、当該レース自身の実際のコーナー通過順を確認したものではない。**この点は
  9節・13節で明記する。
- 本レポート作成のために実行した反実仮想（例: going="稍重"を確定値として与えた場合の
  Suitability再計算）は、既存の`computeSuitabilityV1()`等を変更せずそのまま呼び出した
  結果であり、production dataへは一切書き込んでいない。

## 1. Base Ability の妥当性

| 馬名 | baseAbility | 順位 | 実着順 |
|---|---|---|---|
| ダノンシーマ | 78.3 | 1位 | 3着 |
| ロデオドライブ | 76.7 | 2位 | 2着 |
| ゾロアストロ | 74.8 | 3位 | 1着 |
| バレエマスター | 72.4 | 6位 | 10着 |
| ジュンブロッサム | 72.7 | 5位 | 9着 |
| ボーンディスウェイ | 73.1 | 4位 | 7着 |
| アーバンシック | 72.1 | 7位 | 5着 |
| サヴォーナ | 70.2 | 8位 | 4着 |
| ドゥレッツァ | 67.4 | 11位 | 6着 |
| チェルヴィニア | 69.1 | 10位 | 8着 |
| ステレンボッシュ | 69.4 | 9位 | 11着 |

**上位群（ダノンシーマ・ロデオドライブ・ゾロアストロ）を能力上位群として選定できた
理由**: いずれも直近5走（またはロデオドライブは4走）の平均raceScoreが11頭中トップ3
だった。ダノンシーマは白富士S・比叡S・兵庫特別で3勝を含む高水準、ロデオドライブは
4戦4連対（1着3回）というキャリア実績、ゾロアストロもきさらぎ賞1着・東京スポーツ杯
2着等の実績が反映されている。**Base Ability自体が「馬券に絡む3頭」を正しく絞り込む
主要因になっていたことは、実データから明確に裏付けられる。**

**バレエマスター・ジュンブロッサムを高く評価した理由**: baseAbility自体はそれぞれ
72.4（6位）・72.7（5位）であり、実は「極端に高評価」していたわけではない。両馬が
最終順位で4位・5位まで上がった主因はSuitability側（course/gate適性、2節）であり、
**baseAbility単体は中位評価に留まっていた。**

**Base Ability自体の問題か、別要素で負けたかの切り分け**: 4位バレエマスター・5位
ジュンブロッサムの下落は、baseAbility（中位評価）ではなく、Suitabilityによる押し上げ
分（3節・8節で詳述）が結果に結びつかなかったことが直接の原因であり、**baseAbility
自体の評価が誤っていたとは言えない。** 一方、ダノンシーマ・ロデオドライブ・
ゾロアストロの内部順位逆転（1〜3位の並び）はSuitability・Stage Bのどちらでも
説明できない（8節で詳述）ため、この3頭に限っては**baseAbilityの数値精度（0.1〜3点の
僅差）が、実際のアタマ差レースを言い当てるには荒すぎた可能性**が残る。ただし
これは「baseAbilityの計算式が間違っている」という意味ではなく、「僅差の実力伯仲を
数点の差で言い当てることの本質的な難しさ」（6節・14節の偶然性の議論）として
扱うべきである。

## 2. Suitability の妥当性

### 2-1. 実装されているのはdistance/course/going/gateの4つのみ

「左回り」「新潟外回り」「直線の長さ」「コース形状」といった項目は、Suitability V1に
**個別のcomponentとして実装されていない。** courseコンポーネントは「その馬の直近走に
**競馬場名（racecourse）が完全一致する実績があるか**」だけを見る仕組みであり、
「東京・中京等、似た特性（左回り・広い直線）を持つ他競馬場での実績」を類似度として
評価する機構は存在しない。**これは新規に見つかった構造的ギャップである**（3-A分類、
14節）。

### 2-2. 【重要な自己訂正】ゾロアストロのcourse componentの符号を訂正する

CHECKPOINT14D.2の報告書で、ゾロアストロのcourse適性を「プラス要因: course
（n=1,+微増）」「新潟での1走実績によりcourse適性がわずかにプラス（99.6%）」と
記載したが、**これは誤りだった。** 実コードの出力を再確認したところ、course
component は`raw=98.8% → adjusted=99.6%`であり、**99.6%は中立100%を下回る値
（=マイナス）である。** ゾロアストロの唯一の新潟実績（2025-07-27新潟2歳未勝利、
raceScore=73.9）は、彼女自身の全体平均raceScore（74.8）をわずかに下回っており、
course componentは正しくは「わずかなマイナス」だった。

**訂正後の正しい評価**: ゾロアストロのSuitabilityは、distance（-0.8%）・course
（-0.4%）の**両方がマイナス**で、overallSuitabilityPercent=99.4%という**ネット
マイナス**の補正だった（baseAbility 74.8→effectiveAbility 74.4への減点）。**つまり
ゾロアストロは、Suitability V1による加点を一切受けずに（むしろ減点を受けながら）
勝利した。** これはSuitability V1の予測力について、当初考えていたよりも重要な
示唆を持つ（8節で再論）。

### 2-3. 雨・稍重・瞬発力戦への対応

**予測時点では、Suitability V1のgoing componentは11頭全馬でNOT_EVALUATED
だった**（officialGoingが未確定のため、構造的仕様どおり）。「瞬発力戦」（上がり
勝負になるかどうか）を直接評価するcomponentはSuitability V1に存在しない
（final3F傾向はbaseAbility側のraceScore構成要素の一部でしかなく、Suitabilityの
独立componentではない）。

**反実仮想検証（実コードで実行、production未反映）**: 予測時点のgoing=unknownを
実際の確定値「稍重」に置き換えてcomputeSuitabilityV1()を再実行した。

| アーバンシック | 72.17 | 71.81 | −0.36 |
| サヴォーナ | 69.92 | 69.43 | −0.49 |

**最大の変動でも0.71点にとどまり、上位3頭の内部順位（ダノンシーマ>ロデオドライブ>
ゾロアストロ）は反実仮想でも変化しなかった。** つまり「稍重を正しく反映していれば
上位3頭の逆転を説明できたはず」という仮説は、**今回の反実仮想検証では支持されな

となっているものの、その実態は稀薄化された間接的な証拠であり、強い差別化要因には
なっていない。**したがって「going未反映」は事実として存在する構造的ギャップ
ではあるが、今回の順位ズレの主因だったとは言えない。**

## 3. ペース予測

### 3-1. 実際のペース構造

```
1000m通過: 60.6秒
1400-1600m: 11.0秒
1600-1800m: 11.2秒
1800-2000m(ラスト200m): 12.0秒
→ 上がり3F(1400-2000m) = 34.2秒
→ 後半1000m = 119.6 - 60.6 = 59.0秒（前半より1.6秒速い、いわゆる後傾ラップ）
```

前半やや緩め・後半（特に上がり3F）が速い、典型的な「スロー・瞬発力戦」の
ラップ構成であり、公式のSペース判定と整合する。

### 3-2. AIの事前想定とのズレ

事前予測はpredictedPace="average"だった。実際に接続されていた計算経路
（legacy `predictedPace.ts`の`classifyPredictedPace()`）は、**「逃げ候補が2頭
以上→high」「逃げ候補・先行候補がともに0頭→slow」「それ以外→average」**という
離散的な頭数ルールを使っている。今回、逃げ候補（representativeRunningStyle=
"nige"）は0頭だったが、先行候補（senko、ロデオドライブ・ドゥレッツァ）が2頭
いたため、"else"分岐（average）に分類された。

CHECKPOINT14D.4で並行して算出していたRace Pace Prediction V1（CHECKPOINT14C、
Diagnostic専用、Score未接続）の連続値を見ると、**frontPressure=0.65**
（「先頭を主張する」ことが期待される頭数の期待値）は、閾値2に遠く届かない低い
値であり、実際には「明確に前へ行きたがる馬がほぼいない」構造だったことを示唆
していた。**この連続値をより活用していれば、"slow"判定に近づけた可能性がある。**

**仮説（未検証・今回は結論としない）**: 現在のlegacy判定ルールは「逃げ候補・
先行候補が**共に**0頭でなければaverage」という単純な頭数のAND条件になっており、
「先行候補は複数いるが、いずれも確信度の低い（distribution上分散した）候補で
ある」というケース（今回のロデオドライブ nige25/senko50、ドゥレッツァ
nige0/senko60）を、フィールド全体としては実質的にスローペースになりうる
ケースとして区別できない。continuousPacePressure/frontPressureのような連続値を
使った、より精密な閾値へ改善できる可能性がある——**ただし今回1レースだけでは
検証不十分であり、修正提案はしない**（B分類、14節）。

### 3-3. 上位3頭の内部順位逆転への影響

predictedPace=averageのため、`paceScenarioFactor`は全馬で数学的に中立（100%、
CHECKPOINT14D.4で実証済み）。**したがってペース予測のズレは、finalRaceAbility
（Stage B込みの最終評価値）には一切数値的な影響を与えていない。** ペース予測が
仮に正しく"slow"だったとしても、`paceScenarioFactor`の式`raw=100+5×paceLevelScore
×leanScore`により、**leanScoreが負（前寄り、ロデオドライブ-0.167・ダノンシーマ
-0.067）の馬はプラス、正（差し/追込寄り、ゾロアストロ+0.333）の馬はマイナス**の
補正がついたはずである。つまり**「slowペースを正しく予測していれば、むしろ
ゾロアストロ（差し寄り）が相対的に不利になり、ロデオドライブ・ダノンシーマが
有利になる方向**——実際の逆転（ゾロアストロが最上位に来た）とは逆方向の補正
になっていた可能性が高い。**したがって、ペース予測のズレが今回の上位3頭逆転を
「説明できなかった」ことの埋め合わせにはならない**（むしろペース予測を修正して
いた場合、予測と実結果のズレはさらに拡大していた可能性すらある）。

### 3-4. バレエマスター・ジュンブロッサム・サヴォーナ・アーバンシックとの関係

バレエマスター・ジュンブロッサムはleanScore=0.867（11頭中最も追込寄り、5節参照）。
仮に正しくslow判定されていれば、この2頭はpaceScenarioFactorでマイナス補正を
受けていたはずであり、**予測順位はむしろ実際の下落方向と一致する方向に動いていた
可能性がある**（ただし振幅は±5%以内の小さな補正であり、6着分もの下落を説明できる
規模ではない）。サヴォーナ（leanScore0.067、ほぼ中立）・アーバンシック
（leanScore0.600、やや追込寄り）への影響は限定的だったと考えられる。

のまま、`trackBiasFactor`は観測なし（neutral、confidence=low）で確定していた。
今回ユーザーから提供された情報の範囲では、**当該レース自身の実際の通過順位

参考情報として、前日8/29の赤倉特別（同条件、CHECKPOINT14D.4記録）では前

**Track BiasがStage Bへ正式反映されていた場合に順位が変化した可能性がある馬**:
現時点ではデータ不足のため特定できない。これは3-B分類（データが増えれば改善できる
可能性がある）に該当する。

## 5. 展開・位置取り

当該レース自身のコーナー通過順は入手していないため、各馬の**過去の脚質傾向
（Historical Position Profile、実データ）**から間接的に評価する。

`runningStyleLeanScore`（-1=逃げ寄り〜+1=追込寄り）と実着順の対応:

| 実着順 | 馬名 | leanScore | 脚質分布(nige/senko/sashi/oikomi) |
|---|---|---|---|
| 1着 | ゾロアストロ | +0.333 | 20/0/40/40 |
| 2着 | ロデオドライブ | −0.167 | 25/50/0/25 |
| 3着 | ダノンシーマ | −0.067 | 20/20/60/0 |
| 4着 | サヴォーナ | +0.067 | 0/40/60/0 |
| 5着 | アーバンシック | +0.600 | 0/0/60/40 |
| 6着 | ドゥレッツァ | −0.067 | 0/60/40/0 |
| 7着 | ボーンディスウェイ | +0.467 | 0/0/80/20 |
| 8着 | チェルヴィニア | +0.333 | 0/20/60/20 |
| 9着 | ジュンブロッサム | **+0.867** | 0/0/20/80 |
| 10着 | バレエマスター | **+0.867** | 0/0/20/80 |
| 11着 | ステレンボッシュ | +0.333 | 0/20/60/20 |

**明確な線形相関はない**（例えば9・10着はleanScore最大値のペアだが、11着は
むしろ中位のleanScore）。ただし、**leanScore最大値（最も追込寄り）の2頭
（ジュンブロッサム・バレエマスター）が揃って下位（9・10着）に沈んだ**という
事実は目を引く。仮説として:

> スロー・上がり勝負のレースは一般に差し・追込馬に有利とされるが、**前半から
> 全体が凝縮した隊列で進むため、極端に後方から追い込む戦法は「展開待ち」が
> 難しく、進路を探すロスや不利が生じやすい**——「能力を発揮しやすい展開」と
> 「実際に発揮できたか」は別物である可能性。

**これはn=11・1レースのみの観察であり、統計的な裏付けは無い。** 「能力を十分
発揮できる展開だったか」という観点では、バレエマスター・ジュンブロッサムに
ついては「スローペース自体は本来向いていたはずだが、実際の展開の中で追込が
届かなかった」可能性が高いと推測されるが、実際の通過順データが無い以上、
確定的な結論は出せない（D分類、14節）。

## 6. 斤量

コード監査の結果: **現在のfinalRaceAbility計算は、対象レース（今回）に割り当てられた
斤量（assignedWeight/carriedWeight）を一切使用していない。** `RaceEntryInput.
carriedWeight`はFormal Snapshotに記録用として保存されるのみで、baseAbility・
Suitability V1・paceScenarioFactor・trackBiasFactorのいずれの計算にも入力されて
いない。

唯一斤量に関連するのは`weightScore.ts`（raceScoreの構成要素の5%）だが、これは
**その馬自身の過去走で「その走で背負った斤量が、その走のフィールド中央値からどれだけ
乖離していたか」を評価するものであり、「今回のレースでの相対的な斤量差」を評価する
機構ではない。**

**ゾロアストロ（55kg）がロデオドライブ・ダノンシーマ（各57kg）より2kg軽かった
ことが、アタマ差という結果に影響した可能性**: 現在のモデルはこれを一切評価
していないため、**モデルの予測が「間違っていた」というより「そもそも評価対象に
含まれていない要因」**である。一般的な競馬理論では、2000m戦での2kg差は着差
数センチ〜1馬身弱に相当しうるとされ（`weightScore.ts`自身が採用する目安：2000mで
1kg≒0.2秒≒約1馬身相当）、アタマ差2つという結果に対して無視できない規模である
可能性がある。**ただし、この目安はweightScore.ts内の過去走評価用の暫定値であり、
「今回のレースにそのまま当てはめてよい」という検証はされていない。**

## 7. 3歳馬の成長（ゾロアストロ・ロデオドライブ）

### 7-1. 現在のデータ構造の制約

**repository内には馬齢（age/birthYear）を保持する専用フィールドが存在しない。**
`RacePerformance`型・`HorseAbilityProfile`型のいずれにも年齢情報は無く、
`horseId`の先頭4桁（例: `2023107166`→2023）が生年を表しているという**運用上の
慣行**が存在するようだが、これは正式にドキュメント化された契約ではなく、
全horseIdがこの規則に従うことを保証する検証も現状存在しない。**したがって
「馬齢を客観的に取得する」こと自体が、今回時点では正式な手段を持たない。**

### 7-2. 既存データだけで検証可能な代替アプローチ（提案・未実装）

新しい年齢フィールドを追加せずとも、**「直近5走のraceScoreの時系列トレンド」を
見れば、baseAbility（単純平均）が成長期の馬を過小評価している可能性を検証できる**
可能性がある。実データで試算すると:

- **ロデオドライブ**（4走、古い順）: 72.4 → 77.9 → 77.4 → 79.0
  （新馬戦から一貫して上昇、直近2走はほぼ高水準で安定）
- **ゾロアストロ**（5走、古い順）: 73.9 → 74.9 → 78.5 → 76.5 → **70.2**
  （直近走・皐月賞12着が今シーズン最低のraceScoreであり、**上昇トレンドではない**）

**ロデオドライブについては「直近走ほど重視する加重平均にすれば、baseAbility
（現在76.7）は現在の単純平均より高く出た可能性がある」という仮説は成立しうる。**
一方、**ゾロアストロについては直近走が最も低いスコアであり、「直近重視で成長を
織り込む」という仮説は彼女の勝利を説明しない**（むしろ直近重視ならbaseAbilityは
下がる方向）。**つまり「3歳馬成長仮説」は、ロデオドライブの2着には整合的だが、
ゾロアストロの1着を説明する材料にはならない。**

**繰り返し明記する: 「3歳馬だから一律加点する」という補正は提案しない。** もし
将来検証するなら、「直近走ほど重み付けする」「不利なレース（大敗）を除外せず
そのまま使う」といった、年齢そのものではなく**時系列トレンドという客観的に
測定可能なデータ**を使う設計が望ましい、という方向性のみを研究材料として残す。

## 8. finalRaceAbility：ズレはどの段階で発生したか

計算フロー: `baseAbility → suitability → paceScenarioFactor → trackBiasFactor
→ finalRaceAbility`

CHECKPOINT14D.4で実証済みの通り、**paceScenarioFactor・trackBiasFactorは
今回全馬で中立（100%）だった**（predictedPace=average・track bias観測なしの
ため）。**したがってfinalRaceAbility = effectiveAbility（baseAbility×
suitabilityの時点の値）であり、Stage B以降の段階は今回の順位に一切寄与して
いない。** これは4節・3-3節の反実仮想検証でも裏付けられた（going反実仮想でも
上位3頭の順位は変わらなかった）。

**結論: 今回の順位ズレの発生源は、finalRaceAbilityの計算フローのうち、
最初の2段階（baseAbility・suitability、いずれもStage A）に完全に限定される。
Stage B（paceScenarioFactor/trackBiasFactor）は「ズレの原因」にすらなって
いない——なぜなら今回は文字通り何も計算していない（中立100%固定）に等しい
状態だったため。**

**80/77/74という6点差が、実際のアタマ差×2という結果とどの程度整合するか**:
数値的には全く違う規模に見えるが、baseAbilityの6点差自体は「3頭ともキャリア
最上位クラスの実績を持つ馬同士の、相対的に小さな差」（3頭とも直近成績はいずれも
好調〜安定）であり、**実際の競走では上位馬同士の実力差が僅差の場合、数点の
評価差がそのまま数馬身の着差になるとは限らない。** これは「モデルが間違って
いる」という結論ではなく、「finalRaceAbilityという連続値のスケールと、実際の
着差という物理量のスケールが、そもそも線形に対応するとは限らない」という、
より根本的な設計上の論点である（9節の勝率変換問題とも関連するが、9節は
「点差→確率」の変換、本節は「点差→実着差」の対応という、また別の論点である
ことに注意）。

## 9. 勝率変換（順位予測のズレとは分離して分析）

**本節の内容は`docs/win-probability-calibration-v1-research.md`で既に詳細に
研究済みのため、ここでは要点のみ再掲し、重複した分析はしない。**

- T=10でのwin確率最大/最小比は3.19倍。市場オッズの暗示確率比は約17.6倍。
- この開きは「finalRaceAbility→勝率」という変換（Plackett-Luce、
  Temperature）の設計論点であり、**「AIがどの馬をどう順位付けたか」
  （8節までの内容）とは完全に別の問題である。**
- 前回レポートの通り、今回の結果（ゾロアストロ優勝）だけを根拠にTemperatureを
  変更することはしない。

**順位予測のズレ（8節）と勝率変換のズレ（本節）は、原因も改善アプローチも
独立している**ことを改めて明記する——前者はbaseAbility/suitabilityの精度の
問題、後者は「精度が仮に完璧でも、それを確率へどう変換するか」という別レイヤーの
問題である。

## 13. 最終的な結論（優先順位付き）

### 13-1. 今回の予測で最も成功した部分

**オッズを一切使わない能力評価だけで、11頭中「馬券に絡む3頭」を完全に的中させた
こと**（`docs/2026-niigata-kinen-race-retrospective-20260830.md`で既報）。
本レポートの追加分析でも、この成功がbaseAbilityの序列（1節）に主に支えられて
いたことを確認した。加えて、**ロデオドライブ（差分0）・ステレンボッシュ
（差分0）の2頭の完全一致**も明確な成功事例である。

### 13-2. 今回の予測で最も大きくズレた部分

**バレエマスター（−6）・ジュンブロッサム（−4）** の下落。両馬に共通する
「n=1のcourse/gate evidenceによる押し上げ」「極端な追込脚質（leanScore
0.867）」という2つの特徴が、実際の結果と噛み合わなかった。

### 13-3. ズレの原因として最も可能性が高いものTOP5

1. n=1（単一レース）のcourse/gate evidenceの構造的な脆弱性（バレエマスター・
   ジュンブロッサム、B分類）
2. 極端な追込脚質と、スロー・凝縮した隊列の噛み合わせによる展開の不利
   （仮説、D/E分類）
3. アタマ差2つという、事前予測では原理的に埋めきれない僅差（D分類）
4. 今回のレースにおける斤量差（55kg〜59kg）が、現在のモデルに一切組み込まれて
   いない（F分類）
5. official going/wet evidence未接続（反実仮想検証の結果、影響は最大0.71点と
   小さいことを確認済み、C分類）

### 13-4. 既存モデルの中で修正価値が高い箇所

**今回時点では「これを直せば次は良くなる」と断定できる箇所は無い。** 強いて
挙げるなら、C分類の「official going/wet evidenceの正式接続」は、今回の
影響は小さかったものの、天候・馬場が絡むレースでは今後も反復して発生する
論点であり、Stage B Input Contract（CHECKPOINT14D.3で設計済み）の実装を
進める価値はある。

### 13-5. 現状維持すべき箇所

- baseAbility V1の基本設計（直近5走均等平均）——今回の上位3頭選定成功を
  支えた根幹。
- Suitability V1の「evaluatedのみ平均・NOT_EVALUATEDを100として混ぜない」
  という設計思想——ステレンボッシュの正当な低評価の的中を支えた。
- Plackett-Luce・Temperature=10——別レポートで詳述済み、今回の結果だけでの
  変更は引き続き行わない。

### 13-6. 追加データが必要な箇所

- 当該レース自身の実際のコーナー通過順位データ（5節のE分類を解消するため）
- 過去複数レースにおけるn=1 course/gate evidenceの的中率（B分類①の検証）
- horseIdの生年慣行が全馬で正式に成立しているかの検証（7節、age活用の前提）

### 13-7. 過去レースを使って検証すべき仮説

1. 「course/gate componentがn=1の場合、n>=2以上の場合と比べて的中率が
   有意に低いか」
2. 「continuousPacePressure/frontPressureのような連続値ベースのペース判定
   ルールは、現行の離散頭数ルールより精度が高いか」
3. 「極端な追込脚質（leanScore>0.7程度）は、スローペース×多頭数のレースで
   むしろ不利に出やすいか」
4. 「直近走を重視した加重平均は、3歳馬（あるいは全馬齢共通で）単純平均より
   予測精度が高いか」

### 13-8. 新潟記念だけでは判断できないもの

上記13-7の4仮説すべて。**n=1レースでは統計的検証力が無く、いずれも
「今回そう見えた」以上の結論を出すことはできない。**

### 13-9. 今後30レース程度で検証すべき項目

`docs/win-probability-calibration-v1-research.md`で設計したCalibration
検証（Log Loss/Brier Score）のフェーズ設計と同じ規模感（10→30レース）を
再利用し、上記13-7の4仮説を同じデータセットで並行検証できないか検討する
価値がある——**ただしこれも今回は提案に留め、実行しない。**

### 13-10. 現時点でコード変更してよいもの／まだ変更してはいけないもの

**コード変更してよいもの: 現時点では無い。** 本レポートで洗い出した全ての
仮説は、単一レースの観察に基づくものであり、ユーザーの明示的な指示
（「絶対にやらないこと」節）どおり、Base Ability・Suitability・
paceScenarioFactor・trackBiasFactor・斤量補正・Temperatureのいずれについても
**今回の結果に合わせた変更は一切行わない。**

**まだ変更してはいけないもの**: 上記すべて。特に、2-2節で発見した
「course componentのn=1脆弱性」「極端追込脚質の展開不利仮説」は、n=1レースの
観察であり、次のレースで逆の結果が出れば即座に反証される可能性がある仮説で
あることを強調する。
