## STEP2: CASE C実データ検証結果

CHECKPOINT10.9Cの機械基準（career6走以上・対象条件3走以上・対象条件初回がcareer3走目
以降・**対象条件を除く**raceScoreの時系列順位とのSpearman相関>=+0.5）を、
`data/horses/`全40ファイルの全条件グループに対して**網羅的に再実行**した。

**結果: 追加候補は0件。** CHECKPOINT10.10のCASE C専用ZIP（6頭、うち4頭がChatGPT側の
事前ラベルで「高優先度」とされていた）から機械抽出できた候補はウオッカ1頭のみだった
（10.10で確認済み）ことに加え、production data全体を独立に走査しても新たな候補は
見つからなかった。**現時点で実データから機械的に抽出できるCASE C候補は、
全データソースを通じてウオッカ1頭のみである。**

ウオッカの検証結果（CHECKPOINT10.10で実施済み、再掲）: 対象条件4走のうち、1・2回目
（+4.3, +6.5）は同時期の非対象条件レースも同程度好調であり、成長期との混同が実際に
確認された。一方3・4回目（+3.8, +1.3）は同時期の非対象条件成績が下降していたにも
かかわらず正のdeltaを維持しており、条件固有の信号が残っている可能性を示した。

**評価**: 混入は「常に発生する」わけではなく「発生しうる」レベルであり、n=1の実例からは
一般化できない。**confidence/consistencyだけではこの種の混入を検出できない**
（confidenceはサンプル量、consistencyは符号一致率であり、いずれも「成長トレンドとの
時間的な相関」を評価する仕組みを持たないため）。これはCASE Cの残存リスクとして
technical debtに留め置く。

## STEP3: CASE D外れ値耐性の再検証

CHECKPOINT10.10のCASE C検証ZIPが、副産物として複数のn=3〜4実データを提供した
（成長トレンド候補としては非該当だったが、外れ値耐性の検証には有効に使えるデータ）。

**決定的な実例が見つかった**: ゴールドシップ（中山芝2500m・有馬記念、raw sampleCount=4）

| 走 | rawPerformanceDelta |
|---|---:|
| 2015-12-27 | +0.4 |
| 2016-12-25 | **-7.2**（極端な外れ値） |
| 2017-12-24 | +2.2 |
| （2012年走は初回のためabilityBeforeRace算出不能で除外） |  |

| 集約方式 | 結果 |
|---|---:|
| 単純平均 | **-0.95**（外れ値1件で符号自体が反転し、誤って「苦手」と判定される） |
| 中央値 | **+0.6** |
| trimmed（両端1件除外） | +0.6（中央値と完全一致） |
| winsorized（両端1件をクリップ） | +0.6（同上） |

**単純平均は外れ値1件で結論の符号を反転させてしまう**（-0.95 vs +0.6）ことが、
実データで明確に示された。中央値・trimmed・winsorizedの3方式はすべて同じ値（+0.6）に
収束し、外れ値の影響を受けなかった。

他のn=3〜4実例（ジェンティルドンナ フル版: [5.3,0.7,1.2,-2.5]、キタサンブラック:
[2.6,0.2,2.3]）でも同様に、中央値は単純平均より外れ値1件への依存度が低いことを確認した。

**推奨（STEP3の指示通り、新しい複雑な統計モデルは作らない）**: **中央値を正式推奨とする。**
理由: (a) 実データで単純平均の明確な弱点（符号反転）を確認した、(b) trimmed/winsorizedと
同等の頑健性を実データで示しながら、(c) n=2でも定義可能（trimmed/winsorizedはn<5では
理論上機能しない、CHECKPOINT10.8・10.9B・10.9C参照）という点で最も単純かつ普遍的に
使える。**CASE Dは中央値の採用によって実用上ほぼ解消できたと判断する。**

## STEP4: confidence=high実データ確認

`data/horses/`全体・CHECKPOINT10.9B ZIP・CHECKPOINT10.10 ZIPを合わせて、
raw sampleCount>=5の実例を再探索した。**新たな該当例は見つからなかった。**

| 探索範囲 | raw sampleCount>=5の頭数 |
|---|---:|
| `data/horses/` production data（40ファイル） | 0 |
| CHECKPOINT10.9B ZIP（5頭） | 1（グランアレグリア） |
| CHECKPOINT10.10 ZIP（6頭） | 0 |
| **合計（重複調整後）** | **1頭のみ** |

**該当例（既報告分の再掲）**: グランアレグリア（東京・turf・1600m、raw sampleCount=5、
usableDelta=4）: rawDeltas=[+3.1,+4.6,+3.5,+2.9]、aggregatedDelta（中央値）=+3.3、
evidenceDirection=positive、confidence=**high**、consistency=符号一致率100%・
stdev=0.66（低分散、安定）。

**「仕様が悪い」のか「データ量不足」のかの切り分け**: **データ量不足である。**
根拠: (a) 探索対象を「production data全体」「CASE C専用に新規収集された6頭・89走」まで
広げても、5走以上の同条件反復は依然として1例しか見つからない。(b) これは実際の競馬において、
同一馬が同一competition条件（racecourse×surface×distance）を5回以上走ること自体が
稀であることを反映している（多くの馬は生涯で同一G1条件を3〜4回走るのが上限に近い）。
(c) confidenceの閾値設計自体（0=unknown/1-2=low/3-4=medium/5+=high）に矛盾や不合理は
見られない——グランアレグリア1例では、high帯で「データ量も十分・結果も安定」という
望ましい組み合わせが観測されており、閾値ロジック自体が誤動作している証拠はない。

## 追加実データが必要な場合の具体的な要求（次回ZIP用）

**CASE C用**: career6走以上・同一racecourse×surface×distance条件3走以上・対象条件初回が
career3走目以降、という条件を満たす馬を**5〜8頭**（今回の実績: 6頭中1頭のみが機械基準を
満たしたため、3〜5頭を確実に得るには広めに候補を用意する必要がある）。「対象条件を除く
raceScoreの時系列相関が高い（成長トレンドが明瞭）」という条件は、選定時にChatGPT側で
"見込み"として使ってよいが、Claude側で機械的に再判定するため、外れても構わない
（今回同様、ラベルと機械判定が食い違うこと自体は問題ない）。

**confidence=high用**: 同一racecourse×surface×distance条件を**5走以上**経験した実在馬を
**3〜5頭**。

両方の目的を1つのZIP（8〜10頭程度、CHECKPOINT10.9Aで確認済みの規模感の範囲内）で
兼ねることも可能（5走以上の馬は自動的にconfidence=high候補にもなるため）。CSVスキーマは
CHECKPOINT10.9A・10.10と同一（`raceId,horseId,horseName,raceDate,racecourse,raceNumber,raceName,surface,distance,going,finishPosition,carriedWeightKg,actualRaceTimeSeconds,final3FSeconds,timeGapSeconds,gate,horseNumber,fieldSize,source,sourceUrl`）。
CHECKPOINT10.10で発見した列名の揺れ（`carriedWeight`/`raceTimeSeconds`/`frame`）は
どちらでも受け取れることを確認済みだが、上記の正式列名での提供を推奨する。
